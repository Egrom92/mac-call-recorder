# Запись звонков на Mac

Бесплатная запись звонков на macOS: голос собеседника и ваш голос — в один файл, одной кнопкой в строке меню.
Без OBS и платных программ.

*Free call recorder for macOS: records both sides of a call (Core Audio Process Tap + microphone) from a menu bar button.*

![macOS 14.4+](https://img.shields.io/badge/macOS-14.4%2B-black) ![Swift](https://img.shields.io/badge/Swift-6-orange) ![License: MIT](https://img.shields.io/badge/license-MIT-blue)

## Что умеет

- **Записывает обе стороны разговора.** Собеседника — из звука Mac, вас — с микрофона AirPods (если их нет — с микрофона по умолчанию).
- **Три файла на звонок:** «оба голоса», «я» и «собеседник». Отдельные файлы удобно отдавать в расшифровку и ИИ: сразу понятно, кто что сказал. Разделение можно выключить — тогда сохраняется один общий файл.
- **Окно «Детали»** со шкалами громкости собеседника и микрофона в реальном времени — видно, что запись действительно идёт.
- **Кнопка в строке меню.** ◯ — запись не идёт, красный ● с таймером — идёт запись. Клик открывает меню: «Начать запись» / «Завершить запись», а во время записи — ещё и живые шкалы громкости обеих сторон.
- **Не трогает звонок.** Маршрут звука не меняется: собеседника вы слышите как обычно.
- **Выравнивает громкость.** Оба голоса в итоговом файле звучат одинаково громко.
- **Работает локально.** По умолчанию ничего не отправляется в интернет; всё бесплатно и с открытым кодом.
- **По желанию — свой сервер.** Готовые записи могут сами уходить на ваш сервер (например, в CRM), а в режиме **«Прямой эфир»** звук идёт туда кусками ещё во время разговора — для подсказок по ходу звонка. Оба режима выключены, пока вы не зададите адрес сервера и ключ.

Проверено на звонках с iPhone, принятых на Mac («Вызовы с iPhone», Continuity), с AirPods Pro, на macOS 26 Tahoe (Apple Silicon).
Звонки в FaceTime, WhatsApp, Telegram, Zoom и т. п. тоже должны записываться — захватывается весь звук Mac, — но отдельно на них не проверялось.

## Установка

Нужны macOS 14.4 или новее и [Homebrew](https://brew.sh). Откройте Терминал и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/Egrom92/mac-call-recorder/main/install.sh | bash
```

Или из клона репозитория:

```bash
git clone https://github.com/Egrom92/mac-call-recorder.git
cd mac-call-recorder
./install.sh
```

Установщик:

1. проверяет версию macOS и наличие инструментов разработчика Apple (если их нет — откроет окно установки, после неё запустите установщик ещё раз);
2. ставит через Homebrew **BlackHole 2ch** (бесплатное виртуальное аудиоустройство; macOS спросит пароль администратора) и **ffmpeg**;
3. собирает из исходников **CallTap** и кнопку **«Запись звонков»**;
4. ставит команду `call-recorder`;
5. делает пробную запись на 5 секунд — **macOS спросит у CallTap доступ к записи системного звука и к микрофону, нажмите «Разрешить»**;
6. запускает кнопку в строке меню.

Повторный запуск установщика обновляет программу; записи не трогаются. CallTap подписывается локально, поэтому после его пересборки macOS заново спрашивает разрешения — установщик пересобирает CallTap, только если изменился его код, а в остальных обновлениях разрешения сохраняются. Если после установки BlackHole установщик попросит перезагрузить Mac — перезагрузите.

## Как пользоваться

- **Кнопка ◯ в строке меню** (справа, рядом с батареей): клик (левой или правой кнопкой) открывает меню:
  - **«Начать запись»** / **«Завершить запись»** — запись начинается и сохраняется только этим пунктом, случайный клик по кнопке ничего не запускает. Перед записью программа спрашивает **имя клиента** — оно попадёт в название папки (можно оставить пустым);
  - пока идёт запись, вверху меню — таймер и шкалы «Собеседник» и «Я (микрофон)», они двигаются, пока меню открыто;
  - **«Показать детали…»** — небольшое окно поверх остальных: шкалы громкости «Собеседник» и «Я (микрофон)» в реальном времени (зелёная зона — нормально, жёлтая — громко, красная — перегруз), таймер, кнопка записи и настройка разделения;
  - **«Сохранять голоса отдельно (я / собеседник)»** — включено по умолчанию; если выключить, после звонка сохраняется один файл `<дата>_<время>_<имя>.m4a` с обоими голосами;
  - **«Прямой эфир»** и **«Сервер и ключ…»** — см. [Отправка на свой сервер](#отправка-на-свой-сервер-и-прямой-эфир-по-желанию);
  - папка с записями, последняя запись;
  - **«Запускать при входе в систему»** — включите, чтобы кнопка появлялась сама после перезагрузки.
- **Из Терминала:** `call-recorder on "Имя клиента"`, `call-recorder off`, `call-recorder status`, `call-recorder split on|off` (разделять ли голоса).
- **Записи** лежат в `~/Movies/Записи звонков` — на каждый звонок отдельная папка `ГГГГ-ММ-ДД_ЧЧ-ММ_Имя клиента` с тремя файлами:

  ```
  2026-10-28_14-05_Эрик Эглиенс/
  ├── 2026-10-28_14-05_Эрик Эглиенс — оба голоса.m4a   ← весь разговор
  ├── 2026-10-28_14-05_Эрик Эглиенс — я.m4a            ← только ваш голос
  └── 2026-10-28_14-05_Эрик Эглиенс — собеседник.m4a   ← только собеседник
  ```

  Без имени клиента папка называется просто `2026-10-28_14-05`; вторая запись в ту же минуту с тем же именем получает окончание `_2`.

  Громкость в каждом файле выровнена; час разговора — около 145 МБ на все три файла (около 60 МБ, если разделение выключено).
- **Если на кнопке рядом с таймером появился ⚠︎** — микрофон молчит больше 10 секунд, ваш голос не пишется. Клик по кнопке → «Открыть настройки доступа к микрофону» и разрешите CallTap.

Советы:

- Включайте запись за пару секунд до разговора: AirPods около 2 секунд переключаются в режим гарнитуры, и в это время ваш микрофон молчит (в окне «Детали» видно, когда шкала микрофона ожила).
- Записывается весь звук Mac — на время звонка поставьте музыку и видео на паузу.

### Расшифровка и анализ в ИИ

Отдавайте в ИИ файлы «я» и «собеседник» по отдельности — тогда не нужно угадывать, кто говорит. Например:

> Расшифруй два файла одного телефонного разговора. В файле «я» — мои реплики, в файле «собеседник» — реплики клиента. Собери их в один диалог по времени с подписями «Я:» и «Клиент:».

Файлы идут синхронно и одинаковой длины, поэтому отметки времени в двух расшифровках совпадают. Файл «оба голоса» удобен, чтобы просто послушать разговор.

Если собеседник физически рядом с вами (например, в соседней комнате), его телефон может уловить ваш живой голос — тогда ваш голос тихо слышен и в файле «собеседник». С удалённым собеседником такого нет.

## Отправка на свой сервер и «Прямой эфир» (по желанию)

Для тех, у кого есть свой сервер (CRM), принимающий записи. Без адреса сервера и ключа программа ничего никуда не отправляет.

**Настройка** — в меню **«Сервер и ключ…»** (или в Терминале):

```bash
call-recorder server https://crm.example.com
```

```bash
call-recorder token
```

Вторая команда спросит ключ скрытым вводом. Ключ хранится в `~/.call-recorder/inbox-token` (доступ только у вас), не попадает ни в код, ни в журналы, ни в список процессов.

**Отправка готовых записей.** Когда задан сервер и ключ, после каждого звонка файлы уходят на сервер в фоне: `POST /api/inbox?folder=<папка>&file=me.m4a|them.m4a|mix.m4a`, затем `POST /api/inbox/done?folder=<папка>` — пометка «запись готова». В меню видно «☁︎ Запись отправлена на сервер»; если сети не было — «⚠︎ Запись не отправлена — повторить» (или `call-recorder upload`). Записи на Mac остаются в любом случае.

**«Прямой эфир».** Галочка в меню и в окне «Детали» (по умолчанию выключена; `call-recorder live on|off`). Пока идёт запись, отдельный процесс LiveStream читает файл записи и каждые 0,5 с отправляет две дорожки — `me` (микрофон) и `them` (собеседник) — сырым PCM 16 бит, 16 кГц, моно:

```
POST /api/live/chunk?session=<папка>&track=me|them&seq=<N>
Authorization: Bearer <ключ>
Content-Type: application/octet-stream
```

- `session` — то же имя, что у папки записи; `seq` считается для каждой дорожки отдельно, тишина тоже отправляется;
- при сетевой ошибке или ответе 5xx кусок повторяется до 3 раз, потом пропускается; очередь не больше ~10 с, старые куски выбрасываются; на ответ 409 (разговор закрыт) эфир останавливается;
- в конце записи — `POST /api/live/end?session=<папка>`, затем обычная отправка файлов.

Во время записи в меню и в окне «Детали» видно состояние эфира: «в эфире», «подключение…» или «нет связи». Эфир никак не влияет на запись: если интернета нет или сервер недоступен, запись пишется как обычно. Журнал — `~/.call-recorder/logs/live.log`.

## Как это работает

```mermaid
flowchart LR
    subgraph mac["Mac"]
        call["Звонок<br/>(служба avconferenced)"] -->|"звук собеседника"| airpods["AirPods"]
        call -. "Process Tap:<br/>копия звука" .-> agg
        mic["Микрофон AirPods"] --> agg
        bh["BlackHole 2ch<br/>(только «часы»)"] --> agg
        agg["Приватное aggregate-устройство<br/>CallTap"] --> wav["WAV, 2 канала:<br/>1 — собеседник, 2 — вы"]
    end
    wav -->|"ffmpeg: выравнивание громкости"| me["… — я.m4a"]
    wav -->|"ffmpeg: выравнивание громкости"| far["… — собеседник.m4a"]
    wav -->|"ffmpeg: выравнивание<br/>и смешивание"| both["… — оба голоса.m4a"]
```

| Компонент | Что делает |
|---|---|
| `src/CallTap` → `~/.call-recorder/CallTap.app` | Захват звука на Swift: Process Tap + микрофон → WAV. Фоновое приложение без окна. |
| `src/MenuBar` → `~/Applications/Запись звонков.app` | Кнопка в строке меню: запускает и останавливает запись, показывает таймер и ⚠︎, если молчит микрофон; окно «Детали» со шкалами громкости. Уровни берёт прямо из WAV текущей записи (CallTap дописывает его каждые ~0,2 с), поэтому с CallTap напрямую не связана. |
| `call-recorder.sh` → команда `call-recorder` | Запуск и остановка CallTap, выравнивание громкости и сборка трёх файлов через ffmpeg, отправка записей на сервер. |
| `src/LiveStream` → `~/.call-recorder/LiveStream` | «Прямой эфир»: читает растущий WAV, переводит каждую сторону в 16 кГц моно и отправляет кусками на сервер. Отдельный процесс без разрешений macOS — запись от него не зависит. |

По шагам:

1. **Голос собеседника — через Core Audio Process Tap.** Это API macOS 14.4+ (`CATapDescription`, `AudioHardwareCreateProcessTap`): он даёт копию звука, который процессы отправляют на устройства вывода. CallTap создаёт глобальный tap «все процессы, кроме меня» в режиме *unmuted* — звук копируется, а не забирается, поэтому вы продолжаете слышать собеседника.
2. **Всё в одном устройстве.** Tap, микрофон и BlackHole 2ch собраны в одно приватное aggregate-устройство. Звук собеседника и микрофона приходит в одном и том же цикле обработки, поэтому голоса идут синхронно и не расходятся даже на часовых звонках. BlackHole служит только «часами» (главным устройством) — он стабилен, в отличие от AirPods, которые при переходе в режим гарнитуры меняют частоту (48 → 24 кГц), а иногда и пропадают. Для микрофона и tap включена компенсация дрейфа. Флаг `tapautostart` намеренно не используется: с ним устройство не запускается, пока какое-нибудь приложение не начнёт выводить звук, и в тишине не записывается даже микрофон. Если звук перестаёт поступать — например, AirPods в момент запуска как раз переключаются в режим гарнитуры или переподключились посреди звонка, — CallTap через 3–5 секунд сам пересоздаёт устройство и продолжает писать в тот же файл.
3. **Сначала WAV, потом m4a.** Во время записи звук пишется в `~/.call-recorder/current/*.wav`: канал 1 — собеседник, канал 2 — вы. Если что-то упадёт, запись не потеряется (следующий `call-recorder off` её доделает). При остановке ffmpeg измеряет громкость речи каждой стороны (EBU R128), приводит обе к −20 LUFS (не больше +15 дБ, чтобы не вытягивать шум) и за один проход сохраняет три AAC-файла: «я», «собеседник» и их смесь «оба голоса» (с лимитером, чтобы не было перегруза).
4. **Разрешения принадлежат CallTap.** Скрипт запускает CallTap через `open` как отдельное приложение, поэтому macOS спрашивает разрешения у CallTap, а не у Терминала, и помнит их.

## Почему не работают обычные способы

Когда вы принимаете звонок с iPhone на Mac и говорите в AirPods, звук звонка воспроизводит системная служба **avconferenced**, и она отправляет его **прямо в AirPods** в режиме гарнитуры (Bluetooth HFP), в обход системного выхода. Поэтому:

| Способ | Что происходит |
|---|---|
| Multi-output устройство «AirPods + BlackHole» как системный выход | Звонок всё равно идёт напрямую в AirPods, BlackHole пуст. |
| «Звук рабочего стола» в OBS (ScreenCaptureKit) | Звук звонка туда не попадает. |
| Системный выход = BlackHole, слушать через мониторинг OBS | Звонок переключается на BlackHole, но вы перестаёте слышать собеседника; переключение выхода посреди звонка может «сломать» звук в AirPods до их переподключения. |
| **Process Tap (этот проект)** | Работает на уровне процесса, а не устройства: tap получает копию всего, что avconferenced отправляет в AirPods, при любом выбранном выходе. Проверено: голос собеседника был в записи весь звонок. |

## Решение проблем

| Проблема | Что делать |
|---|---|
| Не видно кнопки в строке меню | На MacBook с «чёлкой» лишние значки прячутся под неё. Кнопка старается встать рядом с батареей; если её не видно — уберите часть значков (перетащите с ⌘) или запустите «Запись звонков» через Spotlight. |
| Собеседник не записывается | Системные настройки → Конфиденциальность и безопасность → **Запись экрана и системного аудио** → разрешите CallTap. Затем начните запись заново. Если CallTap там уже включён (например, после обновления) — выключите и включите его снова. |
| Ваш голос не записывается (на кнопке ⚠︎) | Системные настройки → Конфиденциальность и безопасность → **Микрофон** → разрешите CallTap. Затем начните запись заново. Если CallTap там уже включён — выключите и включите его снова. |
| В окне «Детали» написано «Звук не поступает» | CallTap сам перезапускает захват в течение нескольких секунд. Если предупреждение не уходит — остановите и начните запись снова; если повторяется — положите AirPods в кейс на 15 секунд. Пустая запись не сохраняется — об этом будет сообщение. |
| В AirPods пропал голос собеседника | Положите оба наушника в кейс на 15 секунд и наденьте снова. |
| Сразу после звонка другое приложение пишет «микрофон перестал работать» | AirPods несколько секунд переключаются из режима гарнитуры обратно; повторите попытку. |
| «BlackHole 2ch не найден» | Перезагрузите Mac после установки BlackHole. |
| В записи музыка или уведомления | Записывается весь звук Mac — ставьте их на паузу во время звонка. |

Для диагностики:

```bash
~/.call-recorder/CallTap.app/Contents/MacOS/CallTap procs   # какие процессы сейчас выводят и записывают звук
cat ~/.call-recorder/logs/calltap.log                       # уровни собеседника и микрофона текущей записи
```

`CallTap diag <секунд> <папка>` пишет уровни и отдельные WAV для общего tap и каждого процесса, который выводит звук, — так можно найти, где идёт звук звонка в другом приложении.

## Запись через OBS (по желанию)

`CallTap bridge` пересылает весь звук Mac в BlackHole 2ch; в OBS добавьте источник «Захват входного аудиопотока» с устройством **BlackHole 2ch** и второй — с вашим микрофоном. Системным выходом оставьте сами наушники, а не multi-output с BlackHole, иначе звук задвоится.

## Удаление

```bash
curl -fsSL https://raw.githubusercontent.com/Egrom92/mac-call-recorder/main/uninstall.sh | bash
```

Записи в `~/Movies/Записи звонков` остаются; настройки и ключ сервера удаляются. BlackHole и ffmpeg удаляются отдельно: `brew uninstall --cask blackhole-2ch; brew uninstall ffmpeg`.

## Законность

Правила записи разговоров различаются по странам: во многих нужно предупредить собеседника или получить его согласие. Ответственность за соблюдение законов — на том, кто записывает.

## Структура репозитория

```
install.sh            установка и обновление
uninstall.sh          удаление (записи остаются)
call-recorder.sh      команда call-recorder: on / off / status / live / server / token / upload
src/CallTap/          захват звука: Process Tap + микрофон → WAV (Swift)
src/MenuBar/          кнопка в строке меню (Swift, AppKit)
src/LiveStream/       «Прямой эфир»: звук кусками на сервер во время записи (Swift)
tests/                проверки эфира и отправки на локальном сервере-имитаторе
```

Проверки (не трогают настоящие настройки и ключ, сервер — локальный имитатор):

```bash
bash tests/test-livestream.sh
```

```bash
bash tests/test-upload.sh
```
